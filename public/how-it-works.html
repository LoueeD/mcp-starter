MCP Starter

How this starter works

One Worker, one account, one private MCP connection per client.

Connect in three steps

  1. Create an account with a passkey and give the connection a name plus your app credential.
  2. Copy the private MCP URL into your client’s custom MCP server form and choose No authentication.
  3. Ask the agent to discover the available operations. It will use only what the connection is allowed to use.

Three tools, one contract

The MCP surface is intentionally small. Your app supplies the operations; the agent supplies the arguments.

discover
Return the operations this connection may use, with compact summaries by default, full JSON Schemas on request, and a cursor for larger operation sets.
execute_read
Run list and get operations. Results include pagination metadata so a partial page is never reported as complete.
execute_write
Run create, update and delete operations. Writes are validated, read back and never retried automatically when the outcome is uncertain.

Discovery and execution both check the catalogue version and the connection revision. If either changed, the agent must rediscover before continuing.

You choose the access

Control access sets read, create, update and delete per resource for each connection. New connections start read-only. Write permissions also require read because every write is read back.

Changes apply on the next request. An agent with a stale catalogue receives a structured SCHEMA_CHANGED response and must rediscover. Operations outside the scope are not listed and cannot be called.

You can rename, rotate, disable, enable or revoke a connection. Anyone with the MCP URL can use its permitted operations, so keep it private and never put it in logs or analytics.

Behind the scenes

A Hono app on Cloudflare Workers runs the account UI, the passkey ceremonies and a stateless MCP handler. Each account has its own SQLite Durable Object for passkeys, sessions, connections, access policy and the demo data.

The MCP URL contains an account prefix and a 256-bit secret. Only a SHA-256 hash of the secret is stored; the raw URL is shown once at creation or rotation. App credentials are encrypted with AES-GCM using a versioned keyring supplied as Worker secrets.

The MCP handler validates the token, connection revision and access policy on every request. It holds no session state between requests, so revocation takes effect immediately for new calls.

Replace the demo

The notes resource is a runnable example, not a requirement. Change src/app/catalogue.ts to describe your operations, then replace src/app/demo.ts with calls to your API. The MCP layer, passkeys, connections and access controls stay the same.
